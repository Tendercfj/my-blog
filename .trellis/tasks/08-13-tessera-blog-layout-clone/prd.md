## 2. 目标与用户价值

在当前项目中构建一套与参考网站具有相同信息架构、布局比例、视觉语言、响应式行为和核心交互反馈的博客前端，使访问者能够获得完整、统一且可在桌面端与移动端正常使用的博客浏览体验。

本需求复刻“壳”和“体验”，不复刻参考站的具体内容。最终页面使用本项目自有的中性占位文章、分类、标签、作者信息和本地图片，后续可替换为真实内容源。

## 3. 背景与现状

### 3.1 当前项目事实

- 项目使用 Next.js `16.3.0`、React `19.2.8`、TypeScript、App Router、Tailwind CSS 4 和 shadcn/Base UI。
- 当前只有默认首页与全局布局，尚无博客领域组件、内容模型或多页面路由。
- `app/globals.css` 已存在 CSS variables 与 `.dark` 主题基础，可以在实现阶段调整为博客视觉 tokens。
- `lucide-react` 已可用于导航和操作图标，无需为常规图标额外引入图标库。
- 当前仓库没有 CMS、数据库、搜索服务、评论系统或访问统计服务。

### 3.2 参考站实测结论

- 桌面端使用固定顶部导航、组合式 Hero、主内容/右侧栏双栏布局、页脚和右下浮动工具条。
- 首页文章区是两列图片卡片；右侧栏由作者卡、公告、最新文章、分类、标签、归档和网站信息等卡片组成。
- 归档、标签详情和分类详情使用按年份组织的时间线列表，并保留右侧信息栏。
- 标签总览使用多色计数胶囊云；分类总览使用带计数的纵向列表；两者位于大尺寸玻璃卡片中。
- 关于页不使用常规右侧栏，而是个人介绍 Hero、技能胶囊、社交入口、三列统计和正文介绍区域。
- 文章详情使用“大封面标题卡 + 正文卡 + 右侧作者/公告/目录”的结构，正文包含标题、列表、引用、图片和带工具栏的代码块样式。
- 手机端顶部导航保留站名、搜索和菜单入口；Hero、文章列表和侧栏内容改为纵向排列，右侧栏模块堆叠在文章列表之后。
- 参考站 CSS 包含 `1024px`、`900px`、`768px`、`600px` 等响应式边界，并处理 `prefers-reduced-motion`。

### 4.3 明确不在本期范围

- 与参考站进行逐像素复制；验收以结构、比例、层级、视觉语言和响应式体验一致为准。

## 5. 信息架构与路由

本地路由保留参考站的页面语义，不复制其日期型文章 URL 和具体 slug。

| 本地路由 | 页面 | 参考页面 | 主要目的 |
| --- | --- | --- | --- |
| `/` | 首页 | `/` | Hero、文章卡片、右侧信息栏 |
| `/archives` | 归档 | `/archives/` | 按年份浏览所有文章 |
| `/tags` | 标签总览 | `/tags/` | 以计数胶囊展示标签集合 |
| `/tags/[slug]` | 标签详情 | `/tags/linux/` | 展示指定标签的文章时间线 |
| `/categories` | 分类总览 | `/categories/` | 展示分类列表与文章数量 |
| `/categories/[slug]` | 分类详情 | `/categories/linux/` | 展示指定分类的文章时间线 |
| `/about` | 关于 | `/about/` | 独立个人介绍与站点说明布局 |
| `/posts/[slug]` | 文章详情 | 参考站日期型文章详情 URL | 展示文章标题卡、正文和目录 |

不存在的文章、标签或分类 slug 应进入项目统一的 Not Found 页面，不得渲染空白页或抛出未处理错误。

## 6. 全局体验要求

### R1. 全局视觉系统

- 使用系统无衬线字体栈，中文优先兼容 `PingFang SC` 和 `Microsoft YaHei`；正文基准字号约 `15px`，正文行高不低于 `1.8`。
- 浅色模式以 `#425aef` 为品牌主色、`#f7f9fe` 为页面背景、`#4c4948` 为正文色。
- 卡片使用半透明浅色背景、细边框、`12px` 左右圆角、轻阴影和约 `10px` 的玻璃模糊效果。
- 深色模式使用对应语义 tokens，不直接为每个组件散落硬编码颜色。
- 页面背景可使用低对比度的几何装饰，但不得干扰文字阅读，也不得直接复用参考站背景资产。
- hover 阴影和位移动效应克制，常规过渡建议在 `150–300ms` 之间。

### R2. 顶部导航

- 导航固定在视口顶部，高度以参考站约 `56px` 为视觉基线，并具有半透明背景和背景模糊。
- 桌面端左侧显示本项目 Logo/站名，右侧显示搜索、首页、归档、标签、分类和关于入口。
- 当前路由的导航项有可感知的激活态；站名链接回首页。
- 手机端隐藏完整菜单，仅保留站名、搜索和汉堡菜单；点击汉堡菜单打开侧边抽屉，包含站点摘要、内容统计占位和全量导航。
- 打开抽屉或搜索弹层时锁定背景滚动；支持点击关闭、关闭按钮与 `Escape` 键关闭，并正确管理焦点。

### R3. 通用页面框架

- 桌面端内容最大宽度以约 `1400px` 为基线，并在视口中居中。
- 常规双栏页采用主内容约 3/4、侧栏约 1/4 的比例，列间距约 `16–20px`。
- 主内容、侧栏、标签/分类页大卡和正文卡使用一致的卡片语言。
- 页脚展示本项目自有版权/技术信息，视觉低调，并与页面背景自然衔接。
- 右下浮动操作至少包含主题切换与回到顶部；页面未滚动到阈值前可隐藏回到顶部。

### R4. 响应式规则

- `> 1024px`：完整桌面导航、双列文章卡片、主内容/侧栏双栏布局。
- `769–1024px`：收紧容器与间距，Hero 和主侧栏允许降为更紧凑结构，不截断核心内容。
- `<= 900px`：主内容与侧栏切换为纵向布局，侧栏模块排列在主内容之后。
- `<= 768px`：切换移动导航，文章网格改为单列，Hero 改为纵向组合。
- `<= 600px`：缩小页面边距、卡片内边距、标题字号和浮动按钮尺寸，保证 `390px` 视口完整可用。
- 所有断点下不得出现非预期水平滚动、文字遮挡、交互目标重叠或图片变形。

## 7. 页面需求

### R5. 首页 `/`

#### Hero 区

- 桌面端首屏导航下方展示组合式 Hero：左侧宽幅主视觉卡、右侧竖向推荐卡、左侧下方三张分类入口卡。
- 主视觉卡包含短标题、署名/小标签和自有装饰图形或图标组合；不得复用参考站原文案或图标墙排列。
- 三张分类卡使用统一高度和不同的低饱和强调色，点击进入对应分类详情。
- 推荐卡使用深色渐变并提供清晰 CTA，可链接到本项目关于页或自有项目介绍。
- 手机端按“主视觉、分类入口、推荐卡”的顺序纵向排列，不能依赖横向滚动查看。

#### 文章列表

- 桌面端显示两列文章卡片；每张卡片包含封面、标题、发布日期、分类和两到三行摘要。
- 封面保持统一比例并使用 `object-cover`；标题与摘要超出时截断，不能撑破卡片。
- 整张卡片或明确区域可点击进入 `/posts/[slug]`，hover 时呈现轻微上移/阴影增强。
- 移动端改为单列；至少提供 6 条占位文章以验证列表节奏。

#### 右侧信息栏

- 依次提供作者摘要卡、公告、最新文章、分类、标签、归档和站点信息等视觉模块。
- 作者卡包含本地头像/图形占位、站点介绍、文章/标签/分类数量和可选社交入口。
- 统计均由本地占位数据推导或固定展示，不能请求参考站统计接口。
- 桌面端可对部分模块使用 `sticky`；移动端全部进入正常文档流。

### R6. 归档 `/archives`

- 主内容以“全部文章 + 总数”为标题，文章按年份分组显示时间线。
- 每条时间线项包含小封面、日期和标题；年份节点与普通文章节点有明显层级差。
- 桌面端保留右侧信息栏，移动端堆叠到时间线之后。
- 时间顺序默认从新到旧，至少包含两个年份的占位数据，以验证跨年分组。

### R7. 标签 `/tags` 与 `/tags/[slug]`

- 标签总览使用单张大卡，包含页面标题与可换行的彩色标签胶囊。
- 每个胶囊显示标签名称和文章数；颜色来自一组受控的柔和色板，在浅/深主题下均可读。
- 标签详情页使用与归档一致的时间线结构，标题明确显示当前标签及文章数量。
- 无匹配文章时显示卡片化空状态和返回标签总览的入口。

### R8. 分类 `/categories` 与 `/categories/[slug]`

- 分类总览使用单张大卡和纵向列表；每项包含强调色圆点、分类名称和文章数。
- 分类详情页复用归档时间线形态，标题明确显示当前分类及文章数量。
- 分类项具备 hover、focus-visible 和当前选择反馈。
- 无匹配文章时显示卡片化空状态和返回分类总览的入口。

### R9. 关于 `/about`

- 使用独立于常规双栏页的全宽介绍布局，不展示首页信息侧栏。
- 顶部居中显示本地头像/图形占位、问候语、名称、简介、技能胶囊和社交图标。
- 中部使用三列统计/事实块；移动端可保持三列紧凑排列或改为自适应网格，但文字不得拥挤。
- 下部使用阅读宽度受控的正文区域，包含至少三个内容小节，用于验证长文排版。
- 所有个人信息使用中性占位内容，不能沿用参考站作者资料。

### R10. 文章详情 `/posts/[slug]`

- 顶部为封面标题卡：大幅本地图片、遮罩、文章标题、发布日期、更新时间、分类、字数/阅读时间等本地元信息。
- 正文置于独立大卡中，阅读列宽与行高适合长文；支持 `h2/h3`、段落、链接、有序/无序列表、引用、图片、行内代码和代码块。
- 代码块包含语言标签与复制按钮；复制失败不得中断页面，成功后提供短暂状态反馈。
- 正文末尾可包含版权提示、标签和上一篇/下一篇占位导航，但不得引入真实版权声明或参考站文章链接。
- 桌面端侧栏至少包含作者摘要、公告和目录；移动端目录移入正文顶部折叠区或正文之后。
- 目录链接跳转到对应标题；若实现 P1 滚动高亮，应避免遮挡固定导航。

## 8. 核心交互需求

### R11. 搜索弹层

- 点击搜索入口打开居中或顶部展开式搜索层，包含搜索输入、关闭入口和结果区域。
- 搜索对象限于本地占位文章的标题、摘要、标签和分类；输入后即时过滤。
- 空输入提供引导文案，无结果提供清晰空状态；点击结果进入文章详情。
- 支持 `Escape` 关闭，打开后焦点自动进入输入框，关闭后焦点返回触发按钮。

### R12. 主题与布局偏好

- P0 必须支持浅色/深色主题切换，首次访问可读取系统偏好，用户主动选择后在刷新后保持。
- 主题切换不得导致布局跳动，所有主要卡片、文字、边框、背景装饰和代码块均需适配。
- 单栏/双栏属于 P1；若实现，偏好同样需要持久化，并在不支持双栏的窄屏下自动使用单栏。

### R13. 滚动与动效

- 回到顶部操作使用平滑滚动；当用户设置 `prefers-reduced-motion: reduce` 时改为无动画跳转。
- 导航、卡片和浮动按钮可有轻量过渡，不能使用持续晃动或影响阅读的强动效。
- 懒加载图片时预留宽高，避免明显布局偏移。

## 9. 内容与资产规则

- 占位内容至少包括 6 篇文章、5 个分类、10 个标签和 2 个年份，以覆盖所有页面状态。
- 文章数据在各页面之间保持一致：总数、标签/分类计数、归档年份和文章详情应能互相对应。
- 图片必须来自项目本地的自有/允许使用资产；如暂无素材，使用渐变、抽象 SVG 或明确可替换的本地占位图。
- Logo、站名、作者名称、简介、公告、页脚和推荐卡文案均使用项目自有或中性占位值。
- 外链使用真实可控目标；无有效目标的社交图标不展示，不能链接到参考站作者账号。

## 10. 可访问性、SEO 与质量要求

### R14. 可访问性

- 使用 `header`、`nav`、`main`、`article`、`aside`、`footer` 等语义结构。
- 所有功能图标按钮具有可访问名称，信息图片具有合适 `alt`，纯装饰图片使用空 `alt`。
- 主要流程可用键盘完成，所有交互控件具有清晰 `focus-visible` 样式。
- 文字与背景对比度以 WCAG 2.1 AA 为目标；状态不能只依赖颜色表达。
- 弹层/抽屉具有正确焦点管理、关闭行为和背景滚动控制。

### R15. SEO 与页面元信息

- 每个页面提供与占位内容对应的独立 `title` 与 `description`。
- 文章、标签和分类详情使用稳定可访问的本地 URL；不存在的 slug 返回 Not Found。
- 页面只能有一个主要 `h1`，后续标题层级按结构递进。

### R16. 工程与性能

- 复用当前 Next.js App Router、TypeScript、Tailwind 4、现有 CSS variables 和 `lucide-react`，除非实现证明确有必要，不新增大型 UI/状态依赖。
- 共享框架和重复卡片形态应组件化，页面不得复制大段相同结构。
- 优先使用 Server Components；仅主题、搜索、抽屉、复制等交互区域使用 Client Components。
- 使用 `next/image` 或等价的尺寸约束策略，避免首屏大图造成明显 CLS。
- 不向参考站发起运行时资源请求或数据请求。

## 11. 验收标准

### 11.1 路由与内容

- [ ] AC1：`/`、`/archives`、`/tags`、`/tags/[slug]`、`/categories`、`/categories/[slug]`、`/about`、`/posts/[slug]` 均可直接访问并正常刷新。
- [ ] AC2：无效文章、标签和分类 slug 显示统一 Not Found 或空状态，不产生未处理异常。
- [ ] AC3：全站只展示本项目自有或中性占位内容；代码和 Network 中不存在对参考站正文、个人资料、图片或统计接口的复制/热链。
- [ ] AC4：文章、归档、标签、分类计数在各页面之间一致。

### 11.2 桌面视觉（建议 `1440 × 900`）

- [ ] AC5：首页首屏包含约 `56px` 固定玻璃导航、组合式 Hero、两列文章卡片、右侧信息栏、页脚和右下浮动操作，内容容器居中且不超过约 `1400px`。
- [ ] AC6：常规双栏页的主内容/侧栏比例接近 3:1，卡片圆角、半透明背景、边框、阴影和间距在所有页面一致。
- [ ] AC7：标签总览呈现彩色计数胶囊云，分类总览呈现纵向计数列表，关于页呈现独立 Hero/统计/正文布局，文章详情呈现封面标题卡/正文卡/目录侧栏。
- [ ] AC8：与参考站并排截图比较时，页面模块顺序、宽度关系、层级密度、主色和玻璃卡片语言明显一致；不要求内容和版权资产一致。

## 12. 关键决策

- 复刻目标是参考站的视觉与信息架构，不是内容镜像或主题源码移植。
- 本地文章路由采用 `/posts/[slug]`，不复制参考站的日期型 URL。
- 以静态本地占位数据完成 MVP，确保页面和筛选关系可验证；真实内容系统后续单独立项。
- P0 保留对整体体验影响最大的主题、搜索、移动菜单和回到顶部；单/双栏偏好及复杂动效降为 P1。
- 响应式总体遵循参考站的 `1024/900/768/600px` 层级，但允许在实现阶段根据当前组件的实际溢出点微调，前提是三档验收视口全部通过。

## 13. 风险与后续项

- 参考站视觉包含第三方插画与头像，直接复用有版权和热链风险；本项目必须准备独立占位视觉，因此“内容不同但构图相近”是预期结果。
- 当前项目的 Trellis 前端规范仍处于 bootstrap 状态；实现开始前需先确认最终规范并补充技术设计/执行计划。
- 本 PRD 不定义真实内容接入方式。若后续需要 Markdown、MDX、CMS 或远端 API，应单独明确内容来源、构建方式和安全边界。
- 若将视觉相似度升级为自动化截图阈值，需要先固定字体、测试浏览器、视口、占位图片和基准截图，否则像素差异不具稳定性。

## 14. 阻塞问题

无。本 PRD 已按“只复刻布局样式、不复刻内容”的要求做出最小可执行范围定义，可进入用户评审；评审通过不等同于立即实现，实施前仍需按项目流程补充设计与执行计划。
